## 1. 路线状态

ACTIVE_DEVELOPMENT_CHAIN=CHAIN-M7-LOCAL-PRODUCT-01

~~~

M0～M6 已把契约、运行时、安全工具、持久化恢复、两个场景候选、Web Fixture
和评测工具链合入主分支。它们组成了工程底座，还没有成为一套可连续使用的
本地产品。

M7～M20 的目标是完成一个可在本机完整演示、能够说明企业级边界的智能工单
平台。产品使用本地身份、策略、知识、工具和数据，不连接真实企业网络，不接入
真实员工数据，也不把 Sandbox 结果宣传为企业系统上线。

## 2. 本阶段做什么

保留：

- LiteLLM + DeepSeek V4 Flash 真实模型入口。
- OpenAI/Claude Agents SDK，经统一 Runtime Adapter 运行在受限 LangGraph 节点内。
- FastAPI、Worker、LangGraph、PostgreSQL、Redis 与 Web 的完整本地装配。
- 本地 Keycloak、OPA/Rego、OpenTelemetry 和追加式审计。
- 本地知识库、pgvector、Sandbox MCP 工具。
- 短期记忆、长期记忆和用户画像。
- 智能工单、知识库问答、新员工入职、权限变更、审批辅助五条业务链。
- 固定 120 条功能任务与 36 条安全/故障任务。
- 截图、日志和附件的安全多模态处理。

不进入 M7～M20：

- Jira、ServiceNow、CMDB、HR、IAM 等真实企业系统适配。
- 企业 Vault/KMS/SIEM、生产身份源和生产网络。
- 高可用、跨地域、云生产部署和生产认证。
- 采购领域包。
- 路由 LoRA。

Vendor-neutral Port、Schema、Sandbox 和 Preview 可以保留，用于证明将来能够
替换上游系统；本路线不为厂商逐一实现 Connector。

机器追踪清单中既有的 `FP-ML-001/002` 暂时只保留为历史 `DESIGNED` 条目，
不属于当前交付承诺。删除或退休它们会改变 ContractSet，应在后续契约维护中
单独处理，不能借路线文档修改绕过评审。

## 3. 推进原则

1. 每个里程碑交付一个用户可观察的垂直结果，不只铺接口或目录。
2. 每个 Work Package 只有一个主写目标；超过一个中型模块就拆包。
3. 页面、Trace、执行器和故障入口跟随功能增量建设，不留到最终阶段补齐。
4. 普通增量走 FAST 门禁；跨业务汇合与 M19、M20 走 RELEASE 门禁。
5. 默认使用增量上下文热启动，只读取 Base→Target 变化、当前工作包和直接交接。
6. 按 Agent Registry 选择 2～4 个必要执行者，不向固定七会话广播。
7. 模型负责理解、生成和建议；授权、审批、租户、事实写入和终态由确定性代码负责。
8. 新业务需求在对应工作包激活前，由 S1 分配 Feature ID 并写入 Traceability；
   本路线的里程碑编号不是 Feature 状态证明。

## 5. M7：真实 Provider 与本地运行链

目标：让用户从 Web 发起中文请求，经过真实模型和可恢复运行时得到可观察结果。

交付：

- 在 Model Gateway 后接入 LiteLLM，首个 Provider 使用 DeepSeek V4 Flash。
- 实现 OpenAI/Claude Agents SDK Runtime Adapter；SDK Session 只保存引用，不能
  代替 Task、Checkpoint、审批或执行账本。
- 固定配置名、超时、重试、预算、计量、错误映射和脱敏日志。
- 增加 Provider 限流、熔断、成本上限和故障切换可观测状态。
- 补齐 .env.example、启动前检查和缺少密钥的明确提示。
- 接通 Web → FastAPI → Worker → LangGraph → PostgreSQL/Redis → 只读 MCP。
- 统一 task、run、thread、checkpoint、trace 与 SSE 的关联标识。
- 在 Web 和 LangGraph Studio 展示节点、模型调用、Interrupt、恢复、引用和错误。
- 把离线确定性门禁与在线 Provider Smoke 分开。

退出条件：

- 中文知识问答可以从产品入口进入真实模型节点并返回带来源回答。
- 模型超时、限流、无效响应和缺少密钥均失败关闭，且能从 UI/Trace 定位。
- 在线模型不可用不会使确定性测试失效。

M7 固定拆为四个工作包。WP-070 已热启动，后三个工作包按依赖等待：

1. [`WP-070`](../team/work-packages/WP-070-m7-provider-runtime-adapters.md)：
   LiteLLM、DeepSeek 与 OpenAI/Claude Agents SDK Adapter。
2. [`WP-071`](../team/work-packages/WP-071-m7-local-product-composition.md)：
   API、Worker、Graph、PostgreSQL/Redis 与只读 MCP 装配。
3. [`WP-072`](../team/work-packages/WP-072-m7-web-studio-observability.md)：
   Web、SSE、Studio 和安全可观测投影。
4. [`WP-073`](../team/work-packages/WP-073-m7-product-executors-final-gate.md)：
   首批产品执行器、固定分母与 M7 最终组合门禁。

四包按 `WP-070 → WP-071 → WP-072 → WP-073` 解锁。普通进度不广播给未注册
角色；WP-073 完成后停在用户门禁，不自动启动 M8。

## 6. M8：本地身份与租户

目标：用户身份、工作负载身份和租户上下文由可信边界生成，不由浏览器或模型自报。

交付：

- 本地 Keycloak Realm、Client、测试租户、用户、角色与演示账号。
- OIDC 登录、登出、刷新和会话失效。
- API JWT 签名、issuer、audience、expiry 和 nonce 校验。
- 区分用户身份与 Worker/MCP 工作负载身份。
- 从可信声明构造 SecurityContext，绑定 tenant、role、scope、purpose 和数据分级上限。
- 将租户上下文传递到 API、Graph、MCP Gateway 与 PostgreSQL RLS。
- 提供跨租户、伪造角色、错 audience、过期 Token 和上下文篡改负例。

退出条件：

- 所有产品入口都由可信 OIDC 身份进入。
- 跨租户成功读取和写入为 0。
- 模型输出无法提高权限、改变租户或绕过 RLS。

## 7. M9：本地策略、密钥与 DLP

目标：把授权、审批前置条件、数据泄漏检查和审计变成可版本化的本地治理能力。

交付：

- 版本化 Rego Policy、发布、回滚、缓存和 deny-overrides。
- RBAC + ABAC，覆盖主体、资源、动作、租户、用途、数据分级和风险。
- 本地 Capability Token 与开发用 Secret Provider；凭据只在 Gateway 边界短时使用。
- Prompt、工具参数、工具结果和模型输出的 DLP/注入检查。
- 追加式本地 Audit Store 与 Security Event Store，支持关联、查询和完整性校验。
- 策略拒绝、凭据泄漏、Prompt Injection、恶意 MCP 内容和审批绕过测试。

退出条件：

- 每次敏感读取或写动作都能追溯到策略版本和确定性决策。
- Trace、Audit、Security Event 均不含明文密钥或隐藏思维链。
- 拒绝路径在账本占位和上游调用前停止。

## 8. M10：本地知识平台

目标：把合成知识读取升级为可维护、可授权、带稳定引用的本地知识系统。

交付：

- 文档、版本、租户、ACL、数据分级、有效期和来源模型。
- 本地导入、内容 Hash、增量更新、失效、删除和重建索引。
- PostgreSQL/pgvector 的关键词 + 向量混合检索、重排、去重与过期过滤。
- 检索前租户、ACL、用途和分级过滤，检索后再次验证引用。
- 回答携带文档、章节、版本和片段引用；无证据时明确不知道。
- 本地知识管理页与检索诊断页。
- 错租户、过期文档、低相关结果、恶意文档和引用漂移测试。

退出条件：

- 检索结果可解释、可回查、可失效。
- 未授权文档不进入候选集合。
- 更新文档后旧引用不会悄悄指向新内容。

## 9. M11：短期记忆

目标：保存当前任务真正需要的临时信息，降低长对话膨胀，同时保持可恢复。

交付：

- 短期记忆契约：最近轮次、当前意图、未决字段、已验证事实、引用和待办。
- 确定性摘要、Token 预算、裁剪原因和使用清单。
- 与 Checkpoint 对齐的写入、恢复和终态清理边界。
- Handoff 时按目标 Agent 重新过滤，不继承上游完整消息和工具权限。
- TTL、清理和“本次模型实际使用了什么上下文”的 UI。
- 摘要漂移、字段丢失、超预算、恢复重复和敏感字段泄漏测试。

退出条件：

- 50 轮对话保持硬预算，关键待办与引用不丢失。
- 短期记忆不承担长期偏好和授权事实。
- 每次裁剪与注入都可以解释。

## 10. M12：长期记忆

目标：保存跨任务可复用、可由用户管理的事实，不把模型猜测当成永久真相。

交付：

- 长期记忆契约，包含来源、置信度、版本、用途、有效期和确认状态。
- 区分事件记忆与可复用事实；默认只允许用户确认或可信系统来源写入。
- 保留、重新确认、冲突检测、替换和失效规则。
- 基于向量和结构化条件的检索，强制租户、用途和敏感度过滤。
- 用户可查看、纠正、删除和导出长期记忆。
- 所有读取、写入和删除进入审计。
- 记忆投毒、过期事实、冲突事实、错租户和删除后残留测试。

退出条件：

- 未确认的模型推断不能进入长期事实层。
- 已删除或失效记忆不会继续进入模型上下文。
- 用户能看到“记住了什么、来自哪里、何时使用”。

## 11. M13：用户画像

目标：形成可控的个性化与预填能力，把画像与短期/长期记忆明确分开。

交付：

- 用户画像 Schema、字段分级、来源、版本、新鲜度与变更历史。
- 区分权威属性、用户确认属性和推断偏好。
- 支持部门、岗位、地点、经理、设备、常用系统、语言与通知偏好。
- 冲突优先级：
  实时权威数据 > 用户确认画像 > 有效长期记忆 > 当前短期记忆。
- 画像页支持查看、确认、更正和隐藏；业务表单只预填，不替用户确认。
- 画像投毒、敏感属性推断、陈旧属性和跨租户测试。

退出条件：

- 画像不能授予权限、代替审批或决定终态。
- 每个用于预填或个性化的字段都能显示来源与新鲜度。
- 用户更正后旧值不再影响后续任务。

## 12. M14：企业知识库问答闭环

目标：让员工基于身份和业务目的查询制度、SOP、FAQ 与历史知识，并获得可核验、
可反馈、可继续办理的回答。

交付：

- 中文自然语言提问、多轮澄清和用户画像辅助，但时效性条件必须由用户确认。
- 检索前执行租户、ACL、Purpose 与数据分类过滤，回答保留稳定来源和知识版本。
- 证据不足、知识冲突、内容过期或超出权限时明确说明，不用模型补造结论。
- 用户可以标记已解决、无帮助或知识过期；需要人工处理时带着问题、引用和已确认
  信息进入智能工单草稿。
- 重启恢复、SSE、Studio、Trace、Audit 与知识反馈链路可观察。
- 正常、歧义问题、无结果、冲突知识、过期知识、恶意指令和错租户测试。

退出条件：

- 用户能从 Web 完成提问、查看引用、反馈结果并在必要时转为工单。
- 未通过权限过滤的文档不会进入模型上下文或回答。
- 回答、拒绝和转工单都能追溯到身份、检索条件、知识版本与任务事件。

## 13. M15：智能工单闭环

目标：支持常见 IT 服务请求，并把信息补全与工单草稿做成通用能力。

交付：

- IT 问题分类与动态表单 Schema。
- 多轮补全影响范围、紧急度、期望时间、设备、地点和附件。
- 给出优先级与处理组建议，并展示依据。
- 可编辑工单草稿；用户确认后才执行创建。
- 创建、回读、重复提交、修改后重新确认和失败恢复。
- 通过 Sandbox Notification MCP 展示通知预览、投递状态和失败恢复；通知失败
  不得反向篡改已经确认的工单事实。
- 误分类、字段矛盾、低置信度、超范围请求和恶意输入测试。

退出条件：

- 模型只建议分类、优先级和处理组，最终内容由用户确认。
- 动态字段变化不会绕过审批、Schema 和幂等绑定。

## 14. M16：新员工入职闭环

目标：把设备与权限复合申请升级为面向主管或服务台的完整产品流程。

交付：

- 明确申请人与入职员工，防止身份混用。
- 收集员工、岗位、部门、地点、经理、入职日期等必要字段。
- 并行查询设备标准、库存和权限模板。
- 生成设备与权限两个独立动作计划，经理审批后分别执行。
- 展示关联工单、部分成功、恢复和最终汇总。
- 缺库存、权限模板缺失、审批过期、单动作失败和重复恢复测试。

退出条件：

- 两个动作各自绑定审批、幂等键、账本和回读结果。
- 一个动作失败不会重复或撤销已经确认的外部成功。

## 15. M17：权限变更与撤销闭环

目标：覆盖添加、变更、续期和撤销权限的完整生命周期。

交付：

- 本地权限目录、当前权限快照和目标权限。
- 当前/目标差异、有效期、业务理由和影响分析。
- SoD 与高风险权限检查，按风险选择审批链。
- 执行、回读、到期、撤销和恢复。
- 权限请求、工单、审批、账本与审计关联。
- 自批、越权、过期审批、权限漂移、重复执行和错主体测试。

退出条件：

- 高风险或 SoD 冲突不能由模型自行放行。
- 恢复时重新验证主体、策略、审批和有效期。

## 16. M18：审批辅助

目标：帮助审批人快速理解请求，但不替代审批人作出决定。

交付：

- 待审批列表、摘要、变更前后差异、证据、风险和缺失项。
- SoD 结果、策略依据、影响范围和建议理由。
- 批准、拒绝、退回补充三个操作；支持查看原始材料和时间线。
- 审批绑定动作摘要、工具 Schema、策略版本和有效期。
- 建议与最终人工决定分别存储和审计。
- 诱导性建议、遗漏风险、偏见、过期材料和审批后篡改测试。

退出条件：

- AI 建议不能直接产生批准结果。
- 任何动作或策略变化都会使旧审批失效并要求重新确认。

## 17. M19：五链集成、产品评测与本地演示

目标：汇合前五条业务链，完成可复现的本地核心产品。

交付：

- 统一登录、导航、任务中心、审批中心、知识、记忆和用户画像页面。
- 统一 Agent、Prompt、Model、Policy、MCP 和数据版本视图。
- Trace、指标、Audit 和 Security Event 的本地诊断入口。
- 运营看板与治理控制台，展示 Provider 成本/限流/熔断、策略版本、工具健康度、
  审计完整性和评测状态。
- GitHub CI、覆盖率、锁文件依赖审计和全新环境复现保持持续通过。
- 为五条业务链注册真实产品执行器。
- 120 条功能任务按五链各 24 条分配。
- 36 条安全/故障任务覆盖租户、审批、记忆、工具、恢复和注入。
- Judge 人工双轮校准、单/多 Agent 公平对比和三次可复现运行。
- make dev、make acceptance、五分钟业务演示和三分钟安全演示。

退出条件：

- 156 条 Case 全部进入固定分母，不因失败、跳过或隔离缩小分母。
- 五条链均可从空卷 Compose 在 Web 中完成。
- P0 安全断言全部通过，证据包能在全新环境复算。
- 只有满足验收标准后，才讨论整体 frozen 或发布候选。

## 18. M20：安全多模态

目标：让截图、日志和附件在隔离、扫描和脱敏后服务于排障与审批。

固定管道：

~~~text
原件
  → 隔离区
  → 类型与恶意内容扫描
  → OCR / 日志 / 文档解析
  → PII、密钥、二维码脱敏
  → 隐藏文本与 Prompt Injection 检测
  → 标准化 Observation
  → 只读多模态 Agent
~~~

交付：

- 上传、隔离区和本地对象存储。
- MIME、magic bytes、大小、压缩炸弹和恶意文件检查。
- OCR、截图、日志与文档解析，保留页码、区域和日志行引用。
- PII、凭据和二维码遮罩；原件不直接进入模型。
- 隐藏文字、间接 Prompt Injection 和恶意附件检测。
- 只读 Multimodal Observation Agent，不授予写工具。
- 接入知识库问答、智能工单和审批辅助。
- 文件查看、删除、导出、保留期和审计。

退出条件：

- 原件到模型的旁路为 0。
- 恶意文件、隐藏指令和敏感信息泄漏测试全部通过。
- 多模态结果只作为带引用的观察，不作为授权或执行事实。
- M19 演示和报告更新为最终本地版本。

## 20. 工作包拆分建议

每个里程碑优先拆成以下小包：

1. 契约与领域规则。
2. 后端或运行时实现。
3. Web 与可观测入口。
4. 负向、安全和恢复测试。
5. 跨组件组合验证。

只有同一实现者能够在一个中型模块内完成且门禁低于 R3 时，才允许合并小包。
S7 不参与每个小提交，只在垂直候选汇合和 RELEASE 门禁运行。

M7 使用已经登记的 WP-070～WP-073，不再临时合并为一个长工作包。后续里程碑
沿用相同上限：一个工作包只允许一个主写目标；跨 Owner 装配使用有序子步骤和
精确交接，不让单个 Agent 同时承担 Provider、数据、页面与最终验收。

## 21. 时间估计

M7～M20 预计需要 65～95 个有效工作日。M14/M15 与 M16/M17 可并行，能缩短
自然日，但身份、安全、知识、三层记忆和最终评测不能通过减少负例或跳过门禁压缩。
若单个工作包持续超过 2～3 个有效工作日仍无法形成可验证结果，应立即按主写目标
拆分，不继续扩大同一 Agent 的上下文。

## 22. 统一完成定义

- 代码通过格式、类型、单元、契约、安全和相关集成测试。
- 新接口有版本化契约，新数据有迁移、租户隔离和恢复说明。
- 新工具有 Schema、风险等级、策略、幂等和回读定义。
- 新功能在开始实现前取得 Feature ID，并在完成后更新追踪状态与证据。
- 新失败机理有自动化复现或明确的隔离证据。
- 用户能从页面、Studio、Trace、Audit 或 Security Event 观察关键行为。
- 文档不宣称未经固定数据集和证据复现的性能数字。
